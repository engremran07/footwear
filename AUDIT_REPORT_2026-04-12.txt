BUG FIXED
═══════════════════════════════════════════════════════════

BUG-1 [CRITICAL] — Shop duplicate creation via double-submit race
  File  : app/lib/screens/shop_form_screen.dart
  Root  : _save() lacked a synchronous guard before setState(() => _saving = true).
          In Flutter, pointer events are processed in the same frame before the
          widget rebuilds. Two rapid taps fired two separate Firestore .set() calls
          before the button's onPressed: _saving ? null : _save rebuilt to null.
          The onFieldSubmitted keyboard handler also bypassed the button disable.
  Fix   : Added `if (_saving) return;` as the FIRST statement of _save() —
          synchronous, zero overhead, prevents all double-submit paths.
  Impact: Stops duplicate shop docs from being created. Also fixes potential
          duplicate shop edits from keyboard submit while button save is in flight.

BUG-2 [Stale Rules] — Admin unable to create shops (and other permission-denied)
  Root  : Firestore rules in Firebase were stale — repo rules updated in v3.5.0+43
          audit but `firebase deploy --only firestore:rules` had not been run.
  Fix   : firebase deploy --only firestore:rules,firestore:indexes → SUCCESS.
  Impact: Admin shop creation, seller route-scoped writes, invoice math checks all
          re-aligned with current repo version.
