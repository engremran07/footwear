CONFIRMED FINDINGS
P1 FIXED LOCALLY — A selected super-admin could clear or switch the active
workspace profile context without a same-batch end-audit event. The pre-fix
Rules test reproduced the allowed clear. The client now writes the end event
with the profile transition; Rules validate the prior profile and the updated
profile's end-event pointer. Workspace switches end the old context and start
the new one in the same batch. The final local Rules suite reported 181
passing (37s). Production deployment remains pending.

P1 FIXED LOCALLY — The earlier support-context start path allowed a profile
selection without a matching append-only start event. The client and Rules
now link the exact event ID in both directions. The combined contract is
covered by the Rules suite.

P2 FIXED LOCALLY — The shared amount formatter discarded Arabic-Indic and
Eastern-Arabic digits supported by the canonical amount parser. A
formatter-to-parser regression now covers these scripts.

P1 FIXED LOCALLY — Bulk reset and tenant-backfill scripts that could break
financial/inventory relationships or assign records without ownership proof
were replaced by fail-closed stubs. The scripts were not executed against any
Firebase project.

P1 REVIEW REQUIRED — `promote_super_admin.js` can perform a direct privileged
role patch without the current support-access event contract. It was not run,
changed, or proven obsolete. Keep blocked pending an approved bootstrap
procedure.

P2 BLOCKED — Runtime-configurable permissions are not implemented:
`RoleCapabilities.matrix` is a compile-time role map and Rules independently
authorize each operation. A configurable policy requires a versioned,
validated Rules-enforced contract, approved role/action bounds, cache
invalidation, revocation behavior, and migration. No policy collection or
config schema was invented.

P2 BLOCKED — Feature-by-feature workspace data reset remains fail-closed.
`DatabaseFlushScreen` currently renders its operation entries disabled and
`DatabaseFlushNotifier` throws `UnsupportedError`; its current role and tenant
guards do not constitute an implemented reset workflow. Deletion scope,
dependency order, financial/inventory handling, dry-run preview, idempotency,
recovery, authorization, and audit semantics require a reviewed design.
The existing app flush/reset surfaces remain disabled.

P2 OPEN — Current PDF renderer output and language-aware input behavior still
need end-to-end Arabic/Urdu visual review. Unicode range alone cannot
distinguish Arabic from Urdu; silent language rewriting is not implemented.
