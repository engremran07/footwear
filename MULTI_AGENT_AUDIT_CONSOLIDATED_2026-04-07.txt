CONSOLIDATED TOP FINDINGS (DE-DUPED)
============================================================

[P0-01] Transaction edit mismatch between provider and rules
Severity: CRITICAL
Domain: Security + Financial
Evidence:
- transaction provider update path edits amount/type/etc in app/lib/providers/transaction_provider.dart
- rules update path allows soft-delete fields only in firestore.rules
Risk:
- Seller/admin edit UX can fail with permission-denied
- If provider is changed without matching rules/tests, ledger integrity drift is likely
Recommended action:
- Either restrict UI/provider edit flow to soft-delete only, OR extend rules safely for approved editable fields
- Add provider + rules integration tests for this exact path

[P0-02] allTransactions provider invalidation/guard risk on auth transitions
Severity: CRITICAL
Domain: Security + State lifecycle
Evidence:
- Agent found missing invalidate/guard pattern causing potential stale cross-role cache flash
Risk:
- Transient exposure of admin-scoped transaction data after sign-out/sign-in role switch
Recommended action:
- Add role guard in allTransactions provider (return empty stream for non-admin)
- Ensure auth sign-out invalidates this provider explicitly
- Add regression test for admin -> seller switch

[P0-03] Invoice rules missing amountReceived upper-bound validation
Severity: CRITICAL
Domain: Financial controls + Rules hardening
Evidence:
- Provider validates amountReceived logically, but rules-level enforcement reported incomplete
Risk:
- Direct write bypass could allow amountReceived > total, corrupting outstanding and ledger
Recommended action:
- Enforce amountReceived >= 0 and <= total (+ epsilon tolerance) in firestore.rules
- Add rules test for invalid payload rejection

[P0-04] Data integrity risk in transaction creation with optional/mismatched shop/customer semantics
Severity: CRITICAL
Domain: Financial integrity
Evidence:
- Agents flagged dual-id update and optional id pathways as dangerous in transaction provider
Risk:
- Potential double or orphaned balance updates
Recommended action:
- Normalize to one canonical target id for balance mutation
- Reject mismatched dual-id payloads
- Add atomic batch tests for negative and mismatch cases

[P0-05] Localization parity regression in Urdu map and missing keys used by invoice UI
Severity: CRITICAL
Domain: UX + i18n
Evidence:
- Agent reported truncated/partial Urdu translation map and keys referenced in UI that may be missing
Risk:
- English fallback or raw key leakage on production screens
Recommended action:
- Run strict i18n parity audit (EN/AR/UR key diff)
- Add missing keys and close map integrity issues
- Add localization CI check script

[P0-06] Secret handling concern in Android signing artifacts
Severity: CRITICAL
Domain: Build security
Evidence:
- Agent identified plaintext credential exposure pattern in signing config file
Risk:
- Keystore compromise and release signing risk
Recommended action:
- Rotate exposed credentials immediately
- Move secrets to secure secret store/CI vars
- Confirm keystore files are fully excluded from version control
